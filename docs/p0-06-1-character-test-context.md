# P0-06.1：角色识别专项测试上下文修复

## 结论

失败来自测试夹具没有遵守生产调用契约：它未提供群号、发送者 QQ 标识，也未在调用前初始化群白名单与分群人设。`getLlmReply` 因授权快照变化返回 `reply: null`，随后旧断言对空值调用 `.includes()`。补齐合法的合成身份和存储初始化后，测试进入了实际生产完成路径。

本次只修改了角色专项测试夹具和断言，没有修改生产代码。原有业务断言完整保留；未跳过测试、放宽空值检查或改变记忆授权规则。

## 生产调用契约

| 位置 | 行为 |
| --- | --- |
| `src/main.js` 启动路径 | 在接收消息前读取或初始化模型设置、访问范围，并为获准群初始化独立人设。 |
| `src/main.js` 入站处理 | 先验证群白名单，再将真实群号、当前发送者标识和会话范围传给模型。 |
| `src/llm.js` | 从当前存储重新读取授权状态，并在生成前后核验记忆授权快照。 |
| `src/llm.js` 角色识别路径 | 对图片执行专门的角色识别请求；纯身份问题直接使用识别结论，不继续请求普通聊天模型覆盖它。 |

测试使用虚构群和成员标识，在隔离临时目录中调用公开入口 `getLlmReply`。模型 HTTP 响应由模拟接口提供；没有读取或写入运行实例的设置、聊天记录或数据库。

## 断言保留与加强

原有断言继续要求回复表示未能确认身份、不包含证据不足的角色名，且只发送一次模型请求。本次额外断言：

- 调用状态为 `ok`，不能通过授权取消等空回复状态获得假通过。
- 唯一请求使用生产角色识别指令并携带原图。
- 不会继续调用普通聊天生成；模拟的后续聊天结果故意与角色识别结论矛盾。
- 返回的人设修订号与合成群的实际存储状态一致。
