# 较早转发与跨成员引用的关联修正

日期：2026-10-22（Asia/Shanghai）。所有授权群及白名单私聊共用此流程。

## 实际排查

按用户要求只读查询授权群聊天记录，定位到当日 15:15～15:17 的三条否认转发图片能力的回复。15:15 的追问没有引用原转发，15:16 的请求明确引用了本群 12:07 发送的转发，同时 @了原发送者和 bot。

通过本机 NapCat `get_msg`、`get_forward_msg` 实际取得那条原转发：16 条节点、8 张图片，8 张均返回合法文件标识及 QQ 图片链接，未截取。原消息在同群并晚于现有记忆重置边界。这里只确认展开与图片引用存在，没有下载全部原图或调用模型识图，不能据此声称 8 张图的内容均已识别。

旧版在模型生成前丢失了来源：无引用回查仅同一发送者 3 分钟内的 20 条历史；明确引用也限制在 15 分钟内，并在看到任意其他 @对象时直接退出。模型未获得转发，却将原因误述为接口不支持。

## 修改

- 明确引用原转发：取消 3/15 分钟的关联年龄限制，继续校验同一群/私聊及人设、忘记操作产生的上下文边界。不读取别群或私聊作为当前群材料。
- 同时 @bot 和原发送者：可读取被明确指定的原转发；只 @别人的普通发言不因此触发跨成员读取。昵称明确叫 bot 时也沿用当前授权判断。
- 未引用且明确要求读转发：在当前会话回查最近 24 小时、最多 3 页/300 条历史，可用 @原发送者限定作者。不选择请求发出后才出现的消息，也不将 bot 自己生成的折叠回复当作群友原转发。
- 有唯一候选才关联；多个候选时要求引用指定，明确说最近/上一条时才选最近一条。普通“看看”等模糊短句仍只关联当前发送者 3 分钟内的来源。
- 未找到、多条候选、引用非转发、跨作用域/重置边界、历史查询失败分别提示；明确请求不再把无来源情况交给模型编造接口限制。
- 向最终回复加入实际转发来源时间、节点/图片数、成功读取数和失败阶段说明。没有在最终请求重复附原图，不等于先前的分批观察不存在；模型不能延续旧回复中的错误能力描述。
- 管理页常用功能增加折叠的旧转发关联说明。原有最多九张分批、受限 QQ CDN 下载、GIF 首帧、无群进度消息、发送队列与权限撤销检查继续生效。

## 数据及检查范围

排查辅助程序只允许读取本机历史、消息、转发及图片 API；本轮实际仅查询历史、原消息与转发节点，模型调用和 QQ 发送均为 0。只保留脱敏的计数与时间报告，不把原始聊天、群号、图片链接或文件标识发布到仓库。转发正文仍不自动写入长期知识或表情库。

本轮做修改文件语法检查、静态复核、服务重启与管理页只读查看。没有新增或运行测试，也没有重放真实群友事件或强制调用模型/发群消息。源码修正与实际原转发可展开已有依据；更新后的完整入站→图片下载→模型观察→QQ 回复仍待实际使用观察。不能沿用此前 39 张图读取记录作为本次验收。
