日期：2026-10-22（Asia/Shanghai）。当前阶段为本地源码交付，未重启加载、未推送、未发布。

## 1. 视觉记忆先记后审

完整行为见[临时标注与冲突复审](visual-provisional-memory-20261022.md)。来源明确的单图纠正在现有图片内容检查和虚构角色提取后保存为本群 `provisional`；不再要求联网成功才能有限使用。检索开关关闭或服务故障不会删除临时标注；同图冲突、可靠资料冲突暂停该群同图自动参考，保留双方证据。管理页可选定、撤回、停用、拒绝、编辑和删除。通用参考原记录不被本群改写。

集成审阅修正了两个具体缺陷：管理员撤回到 `candidate` 后不能再被旧候选兼容逻辑重新启用；其他图片的同名已确认角色不能抬高当前图临时标注的置信度。新增来源编号仅在本机保存，不含群聊原文；引用库存表情时来源优先记录实际被引用消息。

现有真实数据不批量迁移；旧候选只有明确指纹与来源且未经管理员处理，才读取投影为临时标注。前端依据 API 工作流标识解锁新操作，旧服务未加载时明确提示，避免新静态页面误报功能已上线。

## 2. 转发回复与长度提示

静态缺口、配置审阅与改动见[转发归因、语气与篇幅](forward-reply-tone-length-20261022.md)。未追读截图原聊天或模型请求；不能确认截图的唯一原因。专用规则已接入分批观察及最终回复，默认只用本次转发材料，阻止无关记忆与人际背景自动混入；默认简要，不再把转发里的攻击变成对当前用户的指责或心理判断。

原长度尾注是程序遇 `finish_reason=length` 时直接追加。新逻辑提高本次转发预算，并区分闭合短正文、疑似断尾及完整性无法确认；判据仍是启发式，不宣称已经判断出上游误报或隐藏推理原因。

## 4. 保留边界

- 明确纠正仍需完成图片内容检查及模型虚构角色提取；这两步服务不可用时，不会编造可用临时记忆。
