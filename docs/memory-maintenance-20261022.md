# 记忆维护：常用索引、完整检索与可恢复归档

日期：2026-10-22（Asia/Shanghai）。参考 [Anthropic memory-management](https://github.com/anthropics/knowledge-work-plugins/blob/main/productivity/skills/memory-management/SKILL.md) 的常用记忆与完整知识分层，适配现有 Node.js + NapCat bot。没有另建办公档案、改写核心人设或启用性格成长。

## 本次完善

1. **按群的常用索引**：最多5条简短词义/别名/互动背景。启用的群知识近期获得多人支持，或在实际检索中至少两次被召回，才可进入索引；30天不再召回/支持会退出常用层，完整知识仍保留。相关知识仍通过现有完整库检索，摘要不能代替正文。候选、拒绝、停用、归档不会进入索引，私聊和其他群不共享。
2. **减少重复提炼**：在已有的同一次提炼调用中，附上当前群的词条名称、别名及当前批次成员的主题命名索引。仅用于对齐同义主题，不附QQ号，不把旧记录计为新证据；引用消息、来源与发送者校验保持原有规则。不保证模型一定识别所有同义说法。
3. **本机定期整理**：bot启动后安排检查，此后每5分钟检查是否到期；每群最多每小时整理一次。合并同群、同成员、同状态且标题/主题和内容完全一致的自动条目，合并去重证据与关键词，将副本归档。不会凭词相似就合并不同含义，也不重新训练模型。
4. **旧记录可查看恢复**：群知识候选30天未获支持归档；成员初步观察14天未获支持归档，对话观察60天淡出、120天归档，本轮明确修正后的自动旧印象立即归档，避免占用当前印象名额；旧版本遗留的已替代记录30天后归档。新版不再按这些规则永久删除内容。管理员确认/拒绝、暂停积累和删除主题保护继续生效；已确认知识不会因不热门被删除。
5. **更谨慎地修正偏好**：不再仅因同主题且同为肯定/否定，就把两段不同的自述混为一条。明确更新自述可修正已有自动印象，包括肯定到肯定的变化；要求新来源晚于旧来源。同主题普通新说法先保留候选，管理员决定过的记录不会自动被覆盖。
6. **前端入口**：知识库和成员印象页均有折叠的“记忆维护”信息与“整理本群记忆”按钮，显示常用词、当前/归档数量与最近整理结果。知识来源筛选可看归档；成员编辑勾选显示归档，可“恢复并确认”后保存。编辑未结束时不执行手动整理；修订号变化返回冲突，防止覆盖新资料。

## 存储与调用

- 现有 `data/knowledge-base.json`、`data/member-impressions.json` 继续保存完整条目；追加归档标记，不迁移到另一个重复知识库。
- 新增 `data/memory-index.json` 只保存群/条目标识、召回计数、时间和维护计数，不保存聊天正文、模型输出或额外人物描述。召回元数据失效不阻止正常回复，也不能作为恢复已删记忆的来源。
- 同一分钟重复检索不累计热度；管理页试搜不累计。次数表示检索曾提供过材料，不能据此声称模型确实在最终回答中采用。
- 成员仍以群号+QQ号匹配，昵称可变；只召回当前发送者的启用印象，不把其他群友的档案自动放入当前人的上下文。“忘记我”清除当前成员资料和对应召回计数，原有暂停及代数保护保留。
- 归档不占成员20条当前印象的名额，仍受原有文件大小等存储边界约束。群知识原有存储边界保留；归档没有变成无限原始聊天存储。
- 定期/手动整理不额外调用模型，不联网、不向QQ群发送消息。新对话提炼仍使用原来的调用节奏，不设每日整理次数额度；这里没有回填历史聊天或编造印象种子。
- `data/`继续纳入私有备份，不发布真实记忆或召回索引到GitHub。修改前已做完整备份。

## 完成与证据边界

本次完成源码/语法检查、部署和管理页只读查看。未新增或运行自动测试，没有伪造群消息、偏好或知识，也没有为验收额外触发真实模型提炼。跨轮真实召回、成员偏好修正、归档恢复及长期整理效果，仍需后续真实使用观察；旧版测试结果不代表本轮回归结果。
