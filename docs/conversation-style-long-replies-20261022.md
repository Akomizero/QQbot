# 从容对话与折叠卡片内分段

日期：2026-10-22（Asia/Shanghai）。按用户连续反馈同时调整防御语气与长回答。

**后续修正：** 用户随后改为长回复直接完整发送，已关闭自动折叠并移除应用正文裁剪。当前行为以[直接完整发送](direct-long-replies-20261022.md)为准；下文折叠方案保留作当时的实现记录，语气调整继续生效。

## 排查结论

只读查询近期授权群回复，发现普通评价请求被以“送命题”等口吻回避，能力反馈被连续自辩放大；实际生效人设写的是温和、耐心、友善、不故意毒舌。不能据此断言某一条提示词是唯一原因，但缺少明确的日常交流规则，历史错误回复也可能被延续。

另查明：500 字一直是默认触发折叠的阈值，原代码未将总回复限制为500字。此前最终正文通常最多保留4000字、讨论生成预算至少2304 tokens，折叠节点主要按1200字切分；短于1200字的多段文字可能仍显示成一大条记录。

## 修改

- 增加共享的日常表达规则，覆盖普通回复、自然接话、主动聊天和 B站分享文案：先接内容，按正常交流理解普通玩笑和反馈；减少反射式拒绝、指责动机、假想被封等话术。被指出漏看或说错时核对并简短修正；有不同意见仍说具体理由，不以逢迎、反复道歉代替内容。
- 保留群人设和成长资料，不改写任何群的角色、固定身份、记忆及隐私权限，也不因本次管理员反馈伪造群内成长证据。拒绝仍按实际允许范围执行，只调整具体、简短的表达。
- 需要长回答时先直接回应，再按主题自然分段，用户要求详细或多段时按需要说明，不以500字折叠阈值收短；普通闲聊和主动发言继续简短。
- 讨论类或明确“详细讲讲/多段/长回复/完整说明”等请求，生成预算提高到至少4096 tokens，与当前管理页已支持的单步上界一致；普通聊天仍使用现有配置。总输出并非无限，供应商仍可拒绝、提前终止或受额度影响。
- 这类长回答的应用正文保留边界由4000提高到16000个 Unicode 码点；达到边界时明确提示，不静默切断或截坏 emoji。来源另附。普通回答仍保留4000字边界；自动发言不因此变长。
- 同一张折叠卡片优先按空行分自然段，独立标题与下一段解释保持在一起；较长段落优先在换行/标点处拆成约600字以内的记录，不依赖模型逐字精确分段。代码围栏内空行不当作段落边界。
- 保留全部传入文字、换行、表情及真实 bot 身份，不伪造多位发送者；没有增加群内普通消息数量或生成调用来逐段续写。段落过多时回到原1200字的有界打包，最多50个节点，避免短段落过多导致原本可折叠的文字退回大段普通消息。
- NapCat 明确拒绝折叠时才回退原普通消息；超时/断线仍视作发送状态不确定，不盲目重发。图文默认设置保留；当前讨论使用文字长回复时才能看到折叠内多条记录，可明确说“长回复”或“文字版”。

## 管理入口

聊天设置 → 长回复发送：查看折叠开关、阈值说明及讨论展开规则。分群人设 → 日常聊天的语气：查看共享表达规则。原有保存流程与分群编辑保持不变。

## 检查与局限

本轮只读查看实际聊天与人设相关语句，做修改文件语法和静态复核、重启、管理页只读查看与备份。没有新增/运行测试，没有强制模型对比生成或发 QQ 测试消息。新语气是否稳定、当前 QQ 客户端多节点卡片的最终显示仍待真实使用观察；源码规则不能保证每条回复绝不出现防御话术，也不承诺无限续写。

本记录不附私人群号、人设全文或原聊天，不将本轮结果冒称为历史测试数量的一部分。
