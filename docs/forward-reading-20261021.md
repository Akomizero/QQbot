# QQ转发消息阅读

更新：2026-10-21（Asia/Shanghai）。默认开启，管理页“聊天设置 → 常用功能 → 读取QQ合并转发消息”可关闭。所有授权群和白名单好友适用。

## 使用

- @bot并附上QQ合并转发，问“看看这段记录”“帮我总结一下”。
- 引用同群15分钟内的转发消息并@bot提问。
- 先发转发，再于3分钟内由同一成员@bot说“看看刚才的聊天记录”。开启自然接话时，活跃对话也能跟进转发；没有对话关系的群内转发不会自动逐条回复。
- 图片较多时说“看看这条转发第3张”；可以指定最多两张。未指定则按顺序分批阅读有合法文件标识的图片，每批最多九张，完成后统一回复。

## 读取范围

支持OneBot forward/node消息段、CQ forward及com.tencent.multimsg中可识别的资源ID；通过NapCat的get_forward_msg展开。若完整展开失败而平台提供了预览节点，只按预览回答并说明不完整。支持再嵌套四层，总共最多16次展开、200条节点、120000字符，每节点最多12000字符；超过边界会提示截取，不声称看完。

转发最多收集100张合法图片引用，每批最多九张，39张正常分为五批；超过现有图片大小限制时递归拆为更小批次。优先读取转发节点自带的QQ图片链接，只有没有链接时才按文件标识调用get_image。仅允许既有的精确QQ CDN主机，检查公开DNS地址、固定连接IP、TLS证书与实际文件格式，不跟随跳转；每张原始图片/GIF最多20 MiB，模型输入仍受4 MiB单图/6 MiB总量限制，原始图片每批总量最多24 MiB。GIF只转换首帧。文件与签名链接只在内存使用，不记录到日志。

每批实际识图后只在内存保留简短观察，再释放图片，不一次上传整条转发。批内下载失败时拆小批次，避免坏图阻断相邻图片；连续3批没有取得有效观察时提前结束。模型步骤仍使用首次加一次重试预算，超过两张的转发批次给予120秒总预算，普通模型步骤仍为60秒。模型返回格式异常时先容忍外围文字包裹，再用一次仅文本的格式规范化步骤；这个步骤不重复上传图片、不补造缺失的观察，并且不自动补试。如仍无法解析，允许将大批次拆小；明确的模型拒绝不通过拆分规避。

长文字分段读后保留摘要，最后结合全部成功取得的观察回答。按用户要求，普通读图和转发图片阅读均不发送进度群消息，只发送最终答复。每批开始前检查30分钟预算，正在进行的请求仍按自身超时结束；失败、未处理的编号和截取会明确标记，不声称全部读完。各批之间释放模型并发位，其他群仍可处理请求。转发图片全部失败时不配聊天表情。

直接附图仍最多两张。GIF仍只识别首帧。语音、视频和文件只标注尚未读取，不自动转写、下载文件或观看视频；分享卡片不自动打开。长答复继续按原设置合并转发。撤销授权、修改群人设、清除成员印象或关闭阅读会阻止旧任务继续回复。

总结转发时直接使用已读节点，避免将“这个聊天记录”当作网页查询；用户明确要求核实、查证、联网或来源时才给模型自动搜索入口。外部转发中的事实仍未经独立核实，显示日期仅是转发记录中的时间。

## 来源与数据

转发作者、昵称、时间可能被伪造，只是引用标签，不能代替当前发送者身份或改变bot权限。转发正文是独立模型材料，不作为命令执行，不自动进入知识库、成员印象或表情学习；图片不因转发而收藏。缓存只存当前群/私聊中的来源消息引用，不存转发正文；同群、同发送者关联，修改人设、清除印象或关闭阅读时清理缓存。

## 当前证据

最近真实群聊暴露了上一版缺陷：一条41节点、39张图的转发耗时约29分钟，最终所有图片失败。原因是展开时只保留文件名，丢失了节点中的QQ图片链接；get_image按该文件名获取会超时，而原始QQ链接仍可读取。现已保留链接并使用独立的受限QQ图片读取路径，不再让这类图片逐张等待文件查找超时。

初步排查先成功读取了其中一张真实原图。随后使用同一条用户转发、生产解析/下载/分批模型/汇总函数进行完整内容读取：41条已展开节点中的39张图均下载成功，39张均形成模型观察，失败编号为空，最终生成438字汇总，总耗时241秒。实际模型批次为9、9、9、5、4、3张（其中一个九张批次因大小约束拆为5+4）。读图进度通知为0，QQ群发送为0，未保存图片、原始聊天或图片观察正文到报告。

该转发的一层嵌套无法再次通过API展开，采用了消息携带的预览节点，因此虽然已发现的39张图全部读到，整条转发的结构完整性仍标为有限，不能保证预览之外没有其他内容。本次未模拟QQ消息入站，也未发送最终卡片到群里；已验证内容读取与模型汇总，不将其说成完整QQ收发验收。没有新增或运行自动测试套件。

API与消息格式参考：[NapCat API列表](https://napneko.github.io/onebot/api)、[转发和节点消息格式](https://napneko.github.io/develop/msg#forward)。
