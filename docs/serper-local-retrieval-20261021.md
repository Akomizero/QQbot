# Serper、网页正文与本地检索

更新：2026-10-21（Asia/Shanghai）。

## 来源

1. 网页搜索：管理页“聊天设置 → 联网搜索来源”选择Serper，使用服务端`SERPER_API_KEY`调用Google搜索结果接口。返回标题、链接、搜索片段和可能的索引日期；不是正文，也不是已核实的发布日期。Serper模式不静默切换Tavily、Exa或B站API，B站关键词检索也走Serper的站点查询。
2. 网页正文：`read_webpage`与通用总结独立读取原网页。Serper模式不调用Tavily Extract，不向原网页转发Serper密钥。继续使用公开HTTPS、DNS地址检查、跳转检查、大小与超时边界。登录页、动态页面或访问限制导致失败时说明未读到正文，不靠搜索摘要编造原文。
3. 本群聊天：`search_group_history`在本机搜索当前群近期缓存，最多15分钟、20条普通文字，最多返回10条；不查其他群，不代表完整聊天档案，重启后可能缺失。原有NapCat本机历史预热可补近期消息，不调用网页搜索服务。
4. 本地梗词：`search_meme_knowledge`使用现有按群隔离的本地知识文件。私聊为私聊作用域。只提供相关片段，未启用或不存在时不编造。

明确询问本群聊天、梗词库而没有要求外部查证时，不开放网页搜索与正文工具。工具结果有来源标签和覆盖范围，系统要求回答区分来源。群聊与梗库“本地”指检索过程；需要组织回答的相关片段仍会发送给已配置的模型服务。

## 管理

Serper密钥保存在本机`.env`，前端密码框只写入；GET和保存结果只返回是否配置，不返回已有值。留空保持现有值，也可主动清除。密钥不会写入公开发布副本。现有Tavily配置保留，管理员选择Tavily时才使用其旧备用链。

## Serper连接与重试

Serper请求使用独立连接池，采用bot已配置的专用出口（未配置时按现有代理/直连设置），不再依赖系统全局代理的偶发状态。网络断连、超时、正文传输中断、短暂返回异常、HTTP 408/429/500/502/503/504最多补试两次，总计最多三次请求；单次请求12秒，总预算40秒，通常等待1秒、3秒，限流按Retry-After适度延长。HTTP 400/401/402/403等非临时错误不自动补试。成功、失败与重试的次数和固定错误类别记录在诊断工具阶段`serper_search`，不记录查询、URL、密钥或响应正文。最终失败提示会注明实际补试次数。仍不自动切换其他搜索服务。

## 当前证据与限制

已使用服务端Serper密钥检索其公开官网来源，取得5条`serper.dev`结果，无备用切换；未记录密钥和查询正文到报告。源码语法检查通过。未新增或运行自动测试，未发送QQ群测试消息。完整的“群消息→模型选工具→正文→回复”与分批转发读取仍需实际群聊使用确认。

这次没有增加全量永久聊天档案，也没有把近期缓存称作长期历史。长期梗库、成员印象的积累和遗忘仍由现有功能管理。
