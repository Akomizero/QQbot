# 长回复完整放进合并转发

日期：2026-10-22（Asia/Shanghai）。用户再次明确：长回复折叠在类似转发消息的卡片里。本文取代同日的直接发送方案。

## 当前行为

- 当前服务和新项目默认开启 `longReplyForwardEnabled`，阈值500字。达到阈值的长回复使用QQ合并转发消息；短回复正常发送。阈值只决定发送形式，不限制回答长度。
- 卡片内优先按空行分自然段，短标题与解释放在一起，长段落再拆分。所有节点均使用真实bot身份，不伪造群友发言。保留已生成的全文、来源和换行，不恢复4000/16000字截断。
- 提示词只让模型写完整正文和自然段，转发节点由程序生成。普通闲聊仍保持简短。
- 后台成功重试后的长回复也使用合并转发，沿用权限、人设与成员记忆有效性检查、10秒发送队列及投递回执。折叠时省去不适用于外层卡片的原消息引用段，原消息关联仍保留在恢复任务和回执中。
- 管理页「聊天设置 → 长回复发送」显示开启状态、阈值与卡片内分段说明。默认总结方式为完整文字，较长时合并转发；仍可明确要求图文。

## 已有边界

折叠器每节点最多1200字、每卡片最多50节点；无法构造卡片或NapCat明确拒绝时沿用普通文字回退，不删除正文。超时、断线或投递状态不确定时不盲目重复发送。后台折叠消息取得发送回执后记为已发送；现有读回校验只校验普通文字，未展开转发卡片逐节点核验，不冒充完成这种核验。

「完整」指保留模型实际生成的正文；模型单次输出预算及服务提前结束仍可能限制生成内容，未新增无限续写。
