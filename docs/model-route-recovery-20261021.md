# 模型出口与重试后发送

更新：2026-10-21（Asia/Shanghai）。不含密钥、私人聊天、供应商地址或节点凭据。

## 定位结果

历史故障中，请求常在TLS握手完成前重置；工具成功后生成最终答复也可能失败。单独改IPv4 CONNECT不能保证解决。保持目标接口与客户端一致，使用已有本机代理核心隔离比较三条出口：A成功3/3，原默认B成功0/3，C成功3/3。这里成功指无凭据请求取得预期HTTP401，证明TLS/API可达，不代表完成模型生成。

bot现使用独立、本机回环绑定且带认证的模型出口，A与C组成自动备用组。用户全局代理设置保持原配置。主进程管理专用核心，异常退出后尝试恢复；节点凭据只在本机私有配置保存。

健康模型连接池复用至多2分钟，按服务origin区分；并发初始化合并，连接故障或部分服务错误淘汰池，关闭时排空在途响应，不销毁其他请求的连接。日志增加连接池编号、新建/复用及专用出口标签，不保存正文或密钥。

## 重试和实际发送的区别

普通模型步骤保持首次加一次补试、共享60秒截止时间。补试成功后由正常OneBot发送链路发出一条回复。两次均失败的诊断提示表示当次自动补试已失败，不表示后台还会无限重试。

历史诊断回放默认只验证生成结果，未自动补发到群。此次指定的新诊断已单独补发，并通过get_msg确认同群、自身账号及回复文字一致；用发送账本防止重复补发。其他旧请求没有批量刷回群聊。

## 已验证与边界

- 本机新出口8/8连续探测取得预期HTTP401；实际模型生成已取得HTTP200，工具后续步骤亦成功。
- 群聊可取得历史找到12个诊断号，均已成功生成回复。其中先前成功7个、新诊断成功并已补发1个、换专用出口后复查原失败4个均成功。不是12个都在本轮换线后重测。
- 108/108隔离回归通过，包括重试后真实handler恰好调用一次发送接口、新增连接池与私有出口配置边界，以及分条发图追问。隔离发送使用OneBot替身，与上述真实单条发送回读分开记账。
- 连接可用性取决于节点和供应商，有限探测不能保证后续永久无故障。未做完整备份恢复演练。

## 可选的Windows私有出口配置

`QQBOT_MODEL_PROXY_URL`可覆盖模型请求的代理；一般网页读取继续使用原代理。配置更新需重启进程。不要提交带认证的URL。

可选`.local/model-proxy.json`由管理员提供，包含version=1、已安装FlClashCore.exe的绝对corePath、可选GeoIP资源resourceDir、本机port及params.config。程序通过该核心的本机IPC加载配置，不修改现有代理应用。仅允许127.0.0.1、禁止LAN/TUN/DNS和其他监听器，要求代理认证及1至4个节点。该核心IPC所用配置字段为`rule`，不是YAML的`rules`。没有此私有文件时不会启动专用核心。此集成依赖当前已安装核心的IPC协议；更换核心版本后需复核。

备份包含该私有文件和.env；公开仓库不包含节点、账号、IP或认证信息。核心二进制和GeoIP资源不打包，恢复时保留已有安装或更新本机路径。
