# 看图闲聊不主动查资料与按需引用

## 问题

单张动漫贴图加 @ 的闲聊，可能因角色候选参考触发网页工具，最终一句感受却追加三条百科链接。原普通回复和 illustratedDiscussion 分支都只按搜索结果是否非空附来源。

## 修改

- `src/reply-research-policy.js` 只按当前用户问题判断看图任务是否允许联网，图片内容、角色候选和上下文不能开启搜索。直接图片与包含图片的转发均纳入判断。
- 默认看图/贴图闲聊不提供 web_search、bilibili_search、read_webpage，也不提供无关的视频读取工具。工具执行分支沿用同一开关，模型即使自行返回这些调用也不会执行。
- 明确问角色身份、设定、出处、要求查证/搜索、要来源和显式总结，保留原有检索入口和已有权限限制。普通图片仍可用本地知识、角色识别参考和表情工具。
- 删除“候选角色不熟悉即可联网”的提示。普通看图闲聊明确要求按画面感受接话，不为接话补齐角色资料。
- 普通回复与 illustratedDiscussion 共用来源筛选。网页结果/实际正文带 sourceId；模型只在采用网页事实且出处有帮助时加内部 `[[WEB_SOURCE:编号]]`，应用移除标记后仅追加对应来源，最多三条。
- 用户明确要来源时可直接附本轮来源；明确不要链接时不附。仅搜索过但最终只说感受，不据此附来源。图文的 articles 与 sourceText 同步筛选，避免渲染器再次输出未采用的链接。
- 独立内容总结分支原有日期核实、来源页脚和显式搜索能力保留。

## 影响与限制

普通贴图减少搜索延迟、配额消耗和无关引用。角色身份/设定提问仍可能检索。普通文字问答的自动搜索入口保留。

引用依赖当前兼容模型按事实使用 sourceId 标记；模型遗漏标记时会保守地不附来源，用户明确要来源不受此限制。标记表示本轮实际返回来源的使用意图，不保证其内容真实；原有正文阅读和证据不确定性规则继续适用。自然语言意图为本地关键词规则，没识别到的问法可明确说“搜索/核实”。
