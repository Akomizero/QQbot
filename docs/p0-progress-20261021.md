## 本轮代码修改

### 模型请求

- 每次模型连接使用独立代理连接，有限重试复用原请求；未改服务端模型或代理地址。
- 新增贯穿同一回答的诊断号，记录连接尝试、HTTP状态、代理/直连、耗时、正文中断、JSON解析、空答复、拒绝、截断与工具阶段。界面：聊天设置 → 模型连接与回复参数 → 最近模型请求诊断。
- 修复空回复递归补试的错误被 JSON 解析捕获逻辑重新包装的问题。空choices、空文字、模型拒绝、工具未结束和网络错误分别处理；鉴权/参数错误不当成瞬断反复补试。
- 关闭自动补试后，普通回复的连接层与空答复补试也停止。截断补试后仍有文字时标明长度限制。
- 诊断只保存固定分类、次数和时间，最多80条，不保存正文、图片、URL或密钥。`.local/model-diagnostics.json` 纳入备份。

### 对话对象

- 将当前发送者、bot标识、@目标、引用作者与引用正文单独传入模型，显示名和引用文本仍作不可信素材。
- 引用优先从本群短期缓存读取；不足时仅调用一次 `get_msg`，并核对来源群及人设生效时间。无法核实时说明引用不可用；含凭据的引用不提供正文。
- 引用别人不再仅因短句像追问而自动接话。只@他人、正文偶然提到bot昵称时减少抢话；昵称在开头呼唤bot仍可触发。
- 结构化关系提高上下文质量，不能保证模型在所有多人对话中判断正确，仍需真实会话验收。

### 知识纠正与可见性

- 修复带 `reply` 段的明确纠正被学习入口跳过的问题。明确教学优先安排提炼，但仍遵守每群5分钟间隔及每天12次上限。
- 保存来源指纹与时间、待确认/已拒绝状态；不保存原始聊天或成员身份。引用bot近期已发出的库存表情时，可关联具体表情ID；普通未入库图片不自动建立视觉角色参考。
- 管理页突出待确认数量，新增直接确认/拒绝、已拒绝筛选、来源指纹和关联表情查看。拒绝的候选不被后续学习自动重新启用。
- 发现与已确认知识不同的说法时生成修正候选；确认新版本后停用旧版本，不直接覆盖管理员已确认内容。
- 学习状态、最近保存时间和当天计数持久化到 `.local/knowledge-learning-state.json`；重启不保留原始聊天缓冲。界面区分保存、无新资料、过滤、模型失败、次数用完及缓冲清理。没有新缓冲时“立即提炼”会明确说明。

### 表情偏好

- 新增 `data/sticker-preferences.json`，按群保存特定图片和关键词规则。表情页可确认/驳回群友反馈、添加本群禁用词、逐图禁用或移除规则。
- 明确“别发某某表情”先形成候选，临时避开15分钟；管理员确认后持续禁用。本轮采用此默认流程，未实现成员个人偏好档案。
- 自动选图避开10分钟内最近用过的3张，保留原有每会话30秒间隔；选择时和实际排队发送前均检查禁用规则，防止已排队图片绕过新偏好。
- 关键词只匹配库存名称、标签和用途，不等于自动识别所有图片内角色；优先用逐图禁用控制具体表情。此规则约束库存自动选图，显式 token 原图回发仍走原有内容审核流程。
