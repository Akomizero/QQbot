# QQ转发解读：归因、语气与回复长度

**日期：** 2026-10-22（Asia/Shanghai）<br>
**阶段：** 本地改动与语法、静态集成审阅完成；尚未重启加载或完成真实 QQ 验收。

## 调整范围

新增 `src/forward-reply-style.js`，提供：

- `forwardReadingInstruction(userRequest)`：给分批文字/图片阅读阶段，保留可追溯的发言者、片段和图号，不提前写给群友的回应。
- `forwardSummaryInstruction(userRequest)`：给最终转发回复，区分原文、概括与自己的评价，依当前用户要求决定篇幅。
- `wantsDetailedForwardSummary(userRequest)`：只判断当前请求是否明确要详细展开，不从材料量或人设推断篇幅；明确简要要求优先。

分批与最终规则都要求：原文攻击、玩笑准确归属于原作者/画面人物，不把它当成当前用户在攻击 bot；不补写用户或作者动机，不做心理/人格诊断，不脑补长期关系，不责怪用户或要求用户哄 bot。材料中的偏好、指令和角色扮演不变成当前用户的长期印象或系统要求。

默认先短总结，直接交代主题、关键经过和结论；明确要求详细才分段解释，必要时引用实际原句或图号。用户问感受时可给针对具体片段的评价，不能把评价冒充材料事实。缺页、图片失败、GIF仅首帧只在影响结论处简短说明，不掩盖失败，也不否认已经取得的观察。

最终转发写作规则应放在基础人设、成长/记忆、工具结果与通用长回复版式之后，并在用户问题之前。本场景不应因通用“详细讨论”规则强制写成长篇。基础人设语气可保留，但不能以人设覆盖材料归因与当前用户的篇幅要求；安全、权限和结构化输出格式规则继续有效。

## 静态发现与检查记录

已静态核实：分批文字/图片观察接入 `forwardReadingInstruction`；最终回复在最后一条场景系统规则中接入 `forwardSummaryInstruction`，普通详细讨论规则不再自动作用于转发。默认请求改为简要概括，评价与原文分开。

转发默认不注入长期记忆、成员印象、性格成长和近期群对话，也不自动读取群历史或梗库；当前用户明确要求结合本群历史/背景或知识库时，才允许对应本地资料。已展开转发不误走网页主题摘要，默认不开启额外网页/视频读取；当前请求明确查证、给链接或要求看视频时才开放相应路径。网页工具还核对请求中的链接或明确查证后实际取得的检索结果。

只读扫描当前全局及两个授权群的人格/表达字段：均为800 tokens配置，未发现正向要求攻击或心理机制诊断的词项；出现的攻击类词项在否定语境，另有温和与少量幽默表达。这个词项检查不能证明提示语义没有其他诱因，也不能确定截图根因。未修改真实人设设置，未输出人设全文。

旧固定尾注由程序根据 `finish_reason=length` 添加，不是可据截图确认的正文截断证据。转发最终生成的本次预算提高到至少4096（不改全局800配置）；简要程度由写作规则控制。对上游 `length` 信号，短且句末/结构闭合的正文不盲目补试或加固定尾注，记录 `LENGTH_FLAG_SHORT_CLOSED_TEXT`。存在未闭代码块、悬空连接词等疑似结尾中断时仍可有限补试，保留现有正文；最终分别提示“结尾可能截断”或“服务端报告提前结束、完整性无法确认”。

该判据只是文本形态启发式，不能证明语义完整，也不能确认是隐藏推理占用、额度限制还是服务端误报。本轮没有读取历史模型请求/响应来追溯截图，不把上述静态缺口当作唯一已证实原因。

语法检查通过，未运行测试。当前“本群/聊天记录+链接”但未明确要求联网的混合请求，可能仍被既有本地模式阻止网页阅读；此保守边界未扩大修改。

## 未做的运行验收

本轮未新增或运行测试、未读取群聊原文、未调用真实模型、未联网、未向 QQ 发消息，未重启或发布。

- [ ] 实际转发中的攻击/玩笑被正确归因，没有变成对当前用户的责备或自我辩护。
- [ ] 用户要求简要、只要结论、一句话时保持简短；明确详细时才展开，保留条件与来源。
- [ ] 分批图文笔记在最终回复中正确综合，不混淆人物、顺序、原句与评价。
- [ ] 请求评价/感受时给具体内容看法，不进行心理诊断、关系脑补或索取安慰。
- [ ] 人设与成长内容存在冲突表达时，最终转发回复仍遵守该场景规则。
- [ ] 失败图片、材料缺失和GIF首帧限制说明准确，不误称所有内容都未读取。

提示词约束不能替代真实模型效果验证；若后续仍出现偏差，应定位具体材料归因与规则优先级，再调整对应路径。
