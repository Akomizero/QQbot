# 肥鱼桌面 0.2.2：单次启动、Shell扫码与完整退出

日期：2026-10-23（Asia/Shanghai）。本轮保留了运行中的旧窗口、bot和专用QQ，没有重新登录或停止真实服务。

## 已确认的原因

本机使用的QQ包标记为`isPureShell=true`。它是NapCat Shell版，正常情况下没有普通QQ主窗口。仅调用EnumWindows/ShowWindow无法产生登录界面，也不能把进程存在视为登录完成。

实际只读检查确认：专用NapCat的WebUI已经启动，登录阶段为`waiting_qrcode`，专用工作目录持续产生二维码。旧桌面没有承载这个扫码入口，因而停留在“进程存在但未连接”。官方说明也以NapCat扫码/WebUI作为Shell登录入口：[NapCat文档](https://napneko.github.io/config/starter.shell)。本轮按本机已安装版本的登录接口源码实现，没有猜测登录状态。

另确认专用QQ和其他QQ的Chromium命令行都使用用户原有QQ资料目录。这个共享事实单独展示，不能据此断言它是当前故障原因：当前NapCat已正常进入等待扫码阶段。本轮没有移动、复制、清理或重置任何既有QQ资料；没有修改其他QQ的启动参数和登录态。

## 0.2.2行为

1. **双击EXE自动启动**。先检查系统WebView2、Node版本、Node依赖/图片原生组件、专用NapCat安装、反向WS地址和密钥匹配；缺依赖明确报错，不自动下载安装。
2. 已有未接管的项目后台时，启动只要求确认一次接管与退出语义。旧代码自动加载，不需要用户再点第二次“启动”。其他QQ不在接管范围。
3. **内置“QQ登录”页**显示专用NapCat的二维码，并持续更新。用户只需手机QQ扫码和确认。二维码、WebUI密钥和签发凭据不进入聊天、产品日志或公开分发包。
4. 使用仅由专用QQ进程拥有的本机WebUI监听，读取登录状态；本地鉴权缓存按进程、端口、密钥指纹和有效期核实。支持WebUI在端口冲突后向后递增端口，不连接其他程序的监听。
5. 区分启动Node、初始化、启动NapCat、等待扫码、等待手机确认、QQ初始化、QQ已登录但等待OneBot、就绪和错误。扫码/授权等待不会被当作崩溃反复重启QQ。
6. 仅当**源码摘要一致、新鲜核心健康、NapCat明确报告QQ在线、授权OneBot WebSocket握手已建立**时显示完整就绪，然后打开内置管理页。
7. 二维码过期时按有界间隔自动请求更新；登录未完成时窗口保留等待和下一步提示，不需要再次启动。WebUI二次认证不会被绕过。
8. 关闭主窗口仍执行原来的完整退出：先优雅停止Node/桥接/调度，再停止已登记的专用NapCat/QQ及辅助进程，检查Job与端口归零；失败时保留窗口。没有调用QQ登出或删除登录资料的接口。

`--no-start`用于明确选择只读盘点；正常桌面快捷方式不带此参数。

## 真实验收边界与用户步骤

本轮只读核对真实NapCat：依赖预检通过、源码版本一致、QQ仍在等待扫码。没有替用户扫描/确认，也没有进行真实QQ收发。因此不能把隔离握手称作真实QQ登录完成。
