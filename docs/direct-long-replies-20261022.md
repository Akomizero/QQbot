# 长回复直接、完整发送

**已被后续要求取代：** 用户再次明确长回复应放入合并转发卡片，现已恢复默认折叠，当前行为见[长回复合并转发](folded-long-replies-20261022.md)。下文保留为修改记录。

日期：2026-10-22（Asia/Shanghai）。用户最新要求取代本日稍早的“折叠内多段”方案：长回答默认发送普通文字。

## 已修改

- 当前服务的 `longReplyForwardEnabled` 关闭，新项目默认值也改为关闭。默认摘要输出改为文字；仍可明确要求图文。分群角色、成长、知识和搜索配置保留。
- 移除摘要发送路径里的强制折叠标记。图文排版失败也直接发完整文字，不自动强制转成折叠卡片。
- 移除最终回答的4000/16000字应用截断及来源附加前的正文裁剪，模型实际生成的完整正文和来源都会传给发送层。后台补发同样不再只取前4000字。
- 普通文字按2000个 Unicode 码点的保守单条边界分批，优先在换行或标点处拆分，不截坏 emoji。保留所有字符、段落及图片/引用/提及的原顺序；回复引用不重复追加到每段。这里不是声称 QQ 的固定最大长度为2000，而是本项目的发送边界。
- 同一条长回复的全部分段占用同一个会话发送队列位置，后续消息等待本条发完；每段仍间隔至少10秒，不通过取消限速实现连续发送。每段及等待后重新校验权限和当前任务有效性。
- 只有全部分段发送回执返回后才调用整条成功回调，并返回各段消息 ID。中途取消或发送失败不会当成完整发送；已有分段 ID 附在失败/取消结果中。后台补发的回执保留这些 ID，状态不确定时不盲目整条重发。
- 后台补发读回所有已发分段，将实际文字拼接后核对完整内容哈希，不再只核对最后一段。引用保留在开头，整条完成前不标记为已发完。
- 长回答规则改为自然分段、直接发送完整正文；500字不限制回答长度。保留从容接话的调整，普通闲聊仍简短。管理页说明、摘要文字选项已对应更新。

## 管理入口

聊天设置 → 长回复发送：当前自动折叠关闭。遗留的可选折叠入口仍在，只有管理员之后主动开启才采用；阈值字段在关闭状态不参与正文发送。聊天设置 → 联网阅读与总结：默认选择“完整文字（普通消息）”。

## 检查范围及限制

本轮做修改文件语法/静态复核、配置写入后只读取回对应开关、服务重启和管理页只读查看。没有新增/运行测试，没有强制发起模型调用或向 QQ 发送验证消息。实际分段收发、回执及故障分支还需真实使用观察；不能将页面检查当作真实QQ验收。

“完整发送”指不人为裁掉已生成的正文，并按顺序发送它。模型的单次输出预算、服务拒绝或模型自己提前结束仍影响实际能生成多少内容；没有新增无限续写。分段队列仍在内存，重启/退出会停止尚未发出的普通分段；网络超时或部分发送后失败不具备无条件恰好一次补齐保证。既有后台恢复任务和不确定发送保护继续生效。
