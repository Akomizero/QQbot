## 2. 调用链与覆盖差距

`web.js` → 配置/群人设/成员印象/知识存储 → `llm.js`（群覆盖、正文授权、当前成员选择、实际模型请求）→ `sticker-store.sendLlmResult` → `main.js` 发送守卫 → `reply-queue`/`long-reply` → `onebot.sendMessage` → `protectOutbound` → WebSocket。

最终实现由 `memory-use-guard.js` 把可信作用域、来源内容/授权版本绑定到生成结果。每次模型请求前核对来源状态，模型返回后再核对，发送时将同一守卫带过队列、渲染和转换；OneBot依据实际发送动作和唯一目的地最后核对。此过程使用进程内 Symbol 和 AsyncLocalStorage，不把授权元数据交给模型或QQ。

| 要求 | 基线已有证据 | 本阶段缺口及新增验证方向 |
| --- | --- | --- |
| 群/私聊/当前成员召回 | memory-privacy-impact 13组通过，包含实际请求捕获 | 补充启停/拒绝/归档/删除、连续切群与旧设置对象 |
| 正文授权一致性 | 直接修改磁盘正文后 hash 不匹配 | 尚未验证正式保存接口携带旧 replyAllowed 时是否重新授权新正文 |
| 模型各轮前撤销 | 初次请求前关闭授权 | 补充工具轮次间、模型等待中、删除/正文替换后的旧输出 |
| 最终发送重新授权 | 当前存储仍保留正文时，撤销可替换旧输出 | 删除/改写使旧正文消失后的旧生成结果；图文渲染等待；真实队列阻塞窗口 |
| 发送目的地 | send_msg 的群/私聊及一个转发包 | 动作与 message_type/group_id/user_id 矛盾、缺失/无效/双目标、五种发送动作 |
| 排队/长回复 | 直接检查长回复节点 | 使用正式 coordinator/折叠/fallback/模拟 OneBot 的排队后撤销与分段中撤销 |
| 配置并发/重新授权 | 群人设/成员/知识有 revision | 默认设置无 CAS；授权撤销再启用、相同时间/大小写盘的缓存失效尚未覆盖 |
| 隐私数据仍受保护 | privacy-boundary 14项通过 | 在新增生命周期保护下复跑，验证实际模型/传输包均不含受限值 |

上述差距在本次45组用例中均有对应检查，完整用例名称和通过状态见 `p0-03-test-results.json` 的 `checks`。其中补充了实际HTTP并发保存：同一修订号同时提交两种授权更新，只允许一个成功，另一个409；群人设、成员及知识的旧修订号也不能覆盖新状态。

## 3. 缺陷与修改清单

| 缺陷/根因 | 修复文件与方式 | 回归证据 |
| --- | --- | --- |
| 新建分群配置把私聊默认记忆复制进群档案 | `group-personas.js` 新群长期记忆始终为空，不继承私聊资料 | 私聊/群重复切换、新群存储内容、无群回退 |
| 正式保存成员正文时，旧勾选状态重新生成新正文指纹 | `member-impressions.js` 正文变化时清除授权及指纹，之后可针对新正文再次确认 | 使用正式save接口改正文后不再召回 |
| 固定记忆改正文后沿用原授权 | 群人设及默认设置保存时撤销该正文的原授权；群修订时间严格递增 | 群和私聊正文更新、撤销再启用 |
| 模型调用使用传入的过期设置对象 | `llm.js` 重新读取记忆授权/功能开关和当前白名单；各实际模型轮次核对来源版本 | 删除默认记忆后传入旧对象、禁用开关、工具轮次间撤销 |
| 删除/改写来源后，最终过滤器已不认识旧生成文本 | 新增 `memory-use-guard.js`；`llm.js`、`sticker-store.js`、`main.js`、`reply-recovery.js` 保留生成来源和目的地约束 | 生成等待、群/私聊排队、分段中撤销、图文渲染、主动群聊、补发、转发拒绝后回退 |
| 授权先撤销再启用可能恢复相同字段状态 | 默认设置写入唯一版本；群配置更新时间单调；知识按作用域保存版本；成员保持原generation | 群、私聊及知识重新启用后旧结果不复活 |
| 默认设置缺少旧页面并发保护 | `llm-settings-store.js` CAS修订检查；`web.js` 的记忆变更必须提交当前修订号；`public/app.js` 保存时携带它 | 认证HTTP旧页面覆盖、真实同时提交，两者不能都成功 |
| 隐私缓存只依赖mtime和文件大小 | `privacy-boundary.js` 根据同一次读取的内容生成缓存指纹，JSON也从该快照解析，纳入白名单变化 | 同长度且mtime不变的授权变更仍生效 |
| 发送动作与目的地字段冲突会使用错误的授权范围 | `privacy-boundary.js`、`onebot.js` 对五种发送动作确认唯一合法目标，歧义/缺失/无效目标在传输前拒绝 | 私聊动作夹带群号、双目标、错误类型、无目标及非数字目标 |
| 非普通发送动作跳过传入的allowed守卫 | `reply-queue.js` 对实际发送动作执行守卫；读取动作保持原行为 | 转发守卫拒绝、图片读取主回归 |
| 小于12字符的受保护资料没有匹配项，且部分有效JSON错误结构被接受 | `privacy-boundary.js` 增加短保护句的精确匹配与来源分类，错误存储结构保守阻断 | 未授权短印象、错误groups结构；原有编码/跨群隐私测试 |
| 普通授权漏掉“内部身份/账号/账户”类别 | `memory-reply-access.js` 补入不可分享类别，保留原敏感规则 | 即使普通记忆开关开启，内部身份、账号及密钥仍不进入请求 |

没有删除现有过滤器、扩大白名单或恢复无条件注入。原有逐条成员正文hash、scope隔离和授权默认关闭继续有效。新增安全行为会使有些旧页面保存返回409，正文修改后需要再次确认授权。

## 5. 隐私边界结论

- **群聊**：群A固定记忆、成员召回和知识按来源群使用；群B、错误群ID及已移除白名单的群不能使用它们；新群不存储私聊默认记忆。
- **私聊**：默认记忆需要明确账号授权及当前准入状态；不会因私聊授权回退到群聊。正文修改、撤销或移除准入后，旧请求对象与旧结果不能继续使用。
- **成员印象**：当前发送者相关且已审核/启用/逐条正文授权的非敏感事实才召回。候选、拒绝、归档、替代、删除及成员停用均不召回。这里的既有同意范围是“在来源群回复中使用”，不是仅本人可见的群消息；同群其他人不会无条件取得该人的专属召回提示。
- **撤销与延迟**：各轮模型调用、返回结果、队列等待、分段下一条、图文渲染等待、主动发言和补发均保留来源版本检查。删除正文不会让旧结果躲过校验；撤销后重新启用也不复活旧结果。撤销前已经送出的分段无法撤回，本次证明的是后续尚未发送部分停止。
- **最终发送**：正式OneBot函数从实际action确定群/私聊并拒绝歧义目标；传输前重新验证生成来源及当前边界，不只依赖模型输入或输出阶段。无来源绑定的普通非模型消息仍使用当前文本保护边界，无法凭空识别已删除且不再知晓的任意资料。

## 6. 未解决问题和剩余风险

1. **中**：内容保护仍是确定性的已知字符串/片段及格式匹配，不是任意语义隐私证明；改写、未知编码、外部图片中的隐私不能由这些文本测试穷尽。来源版本守卫解决的是授权时序和目标错用。
2. **中**：没有进行多进程同时写同一配置文件的锁竞争验证。本次证明的是单一管理服务的实际HTTP并发及旧修订号拒绝；独立外部进程绕开正式保存接口写文件不属于已验证管理模型。后续若支持多管理进程，应增加跨进程写锁/CAS测试。
3. **低**：来源版本变化会保守取消正在生成/等待的回复，短受保护句也可能增加误拦。已有无正文计数可辅助观察，不能把计数本身解释成误伤率。
4. **低**：生成来源绑定为进程内状态，未来新增对结果的JSON持久化或新发送入口必须重新生成或显式携带可信来源检查；本次已检查所有现存getLlmReply调用和普通/主动/补发路径。
5. 未验证真实QQ收件、未打包新桌面EXE，也未将分支部署到生产；没有把本地隔离通过称为线上全面安全。
