# 肥鱼 QQ 群聊机器人

自建 Node.js 服务，通过独立运行的 NapCatQQ / OneBot 11 反向 WebSocket 接入 QQ 群聊和好友私聊。提供本机 Web 管理页、分群人设、分群知识、图片和表情处理，以及可选的搜索与内容总结。

## 当前能力

| 功能 | 范围 |
| --- | --- |
| 聊天 | @、昵称呼唤、结合引用关系接话；按会话排队，实际回复至少间隔10秒 |
| 人设 | 每群独立昵称、人设和固定长期记忆；私聊单独处理 |
| 群聊参与 | 合并话轮后判断是否参与；无人回应时暂停主动发言 |
| 知识 | 本机关键词检索、分群积累、待确认/拒绝、来源指纹、修正候选 |
| 成员印象 | 按群号+QQ号积累明确自述；候选审核、修正、停用、删除、忘记与暂停 |

| 表情 | 上传、显式赠送、自动收藏、用途与避免场景、内容审核、分群禁用与近期去重 |

## 安装

需要 Node.js 20.9 或更高版本，以及单独安装并登录的 [NapCatQQ](https://github.com/NapNeko/NapCatQQ)。Windows运维脚本使用PowerShell。其他系统可直接运行Node服务。

~~~powershell
npm ci
Copy-Item .env.example .env
~~~

在本机编辑 `.env`，为 `ONEBOT_ACCESS_TOKEN` 填写新生成的32位以上随机令牌，并填写自己的模型及可选Tavily密钥。密钥仅留在服务端。

~~~powershell
npm start
~~~

默认管理页为 `http://127.0.0.1:3000`。首次打开时自行设置至少12字符的管理员密码。管理认证使用scrypt哈希和HttpOnly会话Cookie。

在NapCat WebUI新增WebSocket客户端：

- 地址：`ws://127.0.0.1:16700/onebot/v11/ws`
- 消息格式：array
- Token：与本机 `.env` 中令牌一致
- 图片读取：按当前NapCat版本开启 `enableLocalFile2Url`，使 `get_image` 返回Base64

在管理页完成：

1. “群与权限”填写自己的群号和允许私聊的好友号。公开版初始白名单为空。
2. “聊天设置 → 模型连接与回复参数”填写自己的OpenAI兼容Chat Completions接口地址和模型ID。公开版接口是占位地址，须先修改；预设模型ID仅是可编辑配置，不保证服务商提供。
3. 按需开启搜索、视觉、知识积累、视频理解与主动聊天；模型调用可能产生服务商费用。
4. “分群人设”编辑各群角色；“知识库”和“表情包”管理本机资料。

`npm run web` 仅启动管理页。`npm run dev` 使用Node watch模式。

## 管理和使用

- “知识库”先选群：单人解释可形成待确认候选，多人支持可自动启用。拒绝不会自动重新启用；对已确认资料的不同说法先形成修正候选。重启不恢复原始聊天缓冲，只保留学习状态、计数和提炼结果。
- “成员印象”先选群：群友明确说“记住，我喜欢……”可直接积累非敏感兴趣，普通自述待审核。修改后点“保存成员”。本群@bot说“忘记我”清除自己的印象并暂停；“继续记住我”恢复积累。
- “表情包”可配置本群逐图/关键词禁用。群友明确说“别发某表情”先临时避开15分钟，管理员确认后持续禁用；最近10分钟用过的3张也会避开。库存选图在实际发送前再次检查规则。
- GIF/图片上传每张最多20MiB，模型输入另行缩小；库最多50张、总量60MiB。自动收藏与手动上传的压缩策略不同。
- 复杂分析可要求详细讨论或图文版。摘要支持游戏以外的新闻、文章、教程等；无法核对“最新”或发布日期时会说明。
- 长回复可用QQ合并转发，图文排版失败时回退文字。客户端、服务商及公开站点可用性仍影响结果。

## 诊断与验证

在“聊天设置 → 模型连接与回复参数 → 查看最近诊断”查看错误类别、HTTP状态、耗时和关联号。诊断不保存正文、图片、接口地址或密钥。鉴权错误、拒绝、空响应、工具未完成和网络中断分别处理。普通回复的每个模型步骤在同一60秒预算内最多请求2次（首次加1次补试），空回复也共用额度；关闭补试则仅1次。工具后续步骤、角色辨认和后台学习是独立任务。视频材料已取得但模型回答失败时会单独说明。模型代理连接使用当前DNS解析的IPv4隧道并保留原域名证书验证；不保证外部网络永久稳定。

~~~powershell
npm run test:p0
~~~

该命令复制源码到忽略的 `.local/p0-verification-*` 目录，使用虚构资料、模拟模型和假OneBot，验证108项P0/P2、成员印象、模型连接与图片上下文行为；不发送QQ消息，不使用正式密钥，不更改正式知识库。报告写入 `.local/p0-check-metadata.json`。保留测试副本便于排查，可在关闭测试后自行删除。

## 视频与常驻（可选）

~~~powershell
powershell -File scripts/setup-video.ps1
powershell -File scripts/install-autostart.ps1
~~~

视频脚本需要Python 3.11+，安装faster-whisper并下载语音模型。Windows常驻脚本安装当前用户登录启动、崩溃恢复，并在运行时抑制自动系统睡眠。真实休眠、注销、关机时本机程序不能运行；NapCat也需自行保持在线。

~~~powershell
powershell -File scripts/stop-bridge.ps1
powershell -File scripts/backup-project.ps1
~~~

备份含本机密钥、认证、知识和表情等运行数据，只能私下保管；不应上传GitHub。备份逐文件校验SHA-256，恢复方式在ZIP内 `RESTORE.md`。公开源码包不能替代运行数据备份。

## 数据与限制

- 服务只绑定 `127.0.0.1`；管理页验证登录和Host/Origin。请勿把初始化页或管理接口转发到公网。
- `data/` 存配置、知识与偏好，`.local/` 存认证、表情、节流和诊断。除示例外均忽略，不随仓库发布。
- 开启模型、搜索或视觉后，相关输入会发送给你配置的服务；知识检索本身在本机运行，命中片段会提供给模型。
- 不含QQ登录会话、NapCat二进制、私人聊天记录、上传表情、服务端密钥、个人固定记忆或开发备份。
- 本项目不执行聊天传来的shell/Skill文件。检索和视频能力是应用内部实现。
- Exa备用搜索不保证严格国内来源；B站搜索只返回元数据，视频理解受字幕、时长和匿名访问限制。原生Google grounding尚未证实。
- 成员印象从部署后的新自述开始，不回填历史；完整角色参考管理页仍未实现。虚构角色识别不能保证覆盖新角色、二创或换装；不猜测真人身份。
- NapCat属于独立第三方接入，请参考其官方说明和许可证。此仓库不包含该项目代码或登录程序。

## 分条发图与连接恢复

所有授权群均支持：先发图片，3分钟内再@bot说‘如何评价’或‘这个图片’，会关联同一成员最近一次图片消息；正在与bot对话时也支持图片追问和45秒内纯图片跟进。引用同群图片可明确指定15分钟内的来源。GIF当前只看首帧。关联按群和发送者区分，按需读取原图，不持久保存聊天图片。详见[图片上下文](docs/image-context-20261021.md)。

模型支持独立的本机认证出口与备用节点、健康连接池复用、失败淘汰及连接诊断。重试成功走正常发送路径，历史诊断回放默认仅记录生成结果。最新108/108隔离回归通过；真实单条恢复回复已发出并回读确认。证据与限制见[专用出口与发送](docs/model-route-recovery-20261021.md)。

## 成员印象：从日常对话逐步形成

成员无需说‘记住’，与AI直接聊天即可形成初步观察；反复支持后自动启用，同主题合并，明确改口更新自动偏好，旧观察逐步淡出或清理。成员积累不设每日次数额度，合并发言并至少间隔5分钟整理；知识库自身的12次限额不阻挡成员积累。管理页直接展示观察内容与支持条数。规则、维护边界和本次运行记录见[说明](docs/member-dialogue-learning-20261021.md)。本轮未新增或重跑自动测试，上文108项结果属于前一版本。

## QQ转发消息阅读

默认开启，可在聊天设置常用功能中关闭。支持@bot附转发、引用转发提问、先发转发再于3分钟内呼唤bot；可读文字、有限嵌套和分批读取图片，并支持‘看这条转发第3张’。语音、视频和文件仅标记未读取，长记录提示截取范围。转发正文不自动写入成员印象、知识库或表情库。使用方式、边界与运行记录见[转发阅读](docs/forward-reading-20261021.md)。本次仅做语法检查和真实API读取，没有新增或运行自动测试。

## Serper与本机检索

可在聊天设置中选择Serper并填写只写入的服务端密钥，统一检索Google结果。正文独立读取原网页，不把搜索片段当成全文。群聊缓存与梗词库独立在本机按群检索；聊天缓存仅最近15分钟20条，不是完整历史。见[来源说明](docs/serper-local-retrieval-20261021.md)。转发图片改为每批最多九张依次读，超出大小限制时拆小批次；读图不发进度群消息，完成后统一回复并明确失败范围，见[转发阅读](docs/forward-reading-20261021.md)。

Serper临时连接故障最多补试两次，总预算40秒，使用bot专用出口连接池；认证拒绝或明确额度不足不重试。详见[来源说明](docs/serper-local-retrieval-20261021.md)。


## ChatGPT 网页生图与后台补发

- 文字生图或最多两张参考图，经本机已登录 Edge 生成，再发回原会话；管理页有独立开关和连接状态。不调用 Codex 生图或 API 兜底。浏览器登录、授权与账户额度仍由 ChatGPT 控制。
- 临时模型/搜索/转发图片故障可在后台最多处理三轮，恢复后引用原请求补发；任务与发送回执落盘，重启继续，状态不确定时不盲目重复发送。
- 详见 [网页生图](docs/chatgpt-web-imagegen-20261021.md) 和 [后台重试与补发](docs/reply-recovery-20261021.md)。网页出图与指定授权群发送已实际使用；未伪造群成员事件，也未故意制造故障来验证所有分支。
- 真正系统睡眠/关机无法运行本机代码；持续服务需要系统保持运行。


## 自主浏览 B站与群分享

肥鱼先看本群正在聊什么，在发言暂歇后从已授权的本机 Edge 首页选片。必须与当前具体话题直接相关；读完视频后再次核对最新讨论，发送前有新发言或bot已回复就取消。没话题或接不上就保持安静。同一聊天快照只评估一次，分享用简短自然接话和原链接。各群独立、重复去重，保留无人回应暂缓与10秒发送间隔，不设每小时/每日分享配额。管理页显示等待话题、等待接话与处理状态。

旧版完成过真实群分享并读回核对；新版自然接话机制已部署，尚待实际群聊观察，不能沿用旧版发送结果作新版验收。浏览器画面回退及全部故障分支尚未专项动态验证。运行需要电脑、Edge、浏览器连接与 bot 保持运行；详见[实现与运行证据](docs/video-discovery-20261021.md)。


## 角色视觉记忆与知识积累

新增「角色记忆」管理页：明确的单图角色纠正经内容检查形成待核实候选。先查维基百科，再补游戏Wiki与官方资料；读取实际正文与参考图，姓名、作品与独特视觉特征证据充分时自动采用，资料不足、搜索失败或身份冲突时保留候选。支持查看核对来源、编辑、手动启用、停用、拒绝与删除，各群隔离。旧管理员参考保留并明确显示范围与标注来源；修改身份或特征后不沿用旧的联网核对结论。

知识提炼不再受每日12次硬上限阻挡，仍合并处理并至少间隔5分钟；知识、成员印象的更新数量分别显示。未人为添加知识凑数，原始聊天缓冲仍不跨重启保留。源码/语法检查和页面只读查看已完成，真实纠正到联网核对、自动采用再识图及后续知识增长待真实使用观察。见[实现与证据范围](docs/visual-memory-knowledge-growth-20261022.md)。


## 记忆维护

按群提供常用词简短索引，需要细节时继续检索完整库。已有主题命名参与同一次对话提炼以减少重复；同主题不同自述不再只凭肯定/否定合并。bot每群每小时在本机整理，完全重复的自动条目合并证据，旧候选和旧观察归档保留，可在知识库/成员印象页查看和恢复。管理员确认、拒绝及暂停保护继续生效。维护不额外调用模型或发送群消息，真实跨轮效果仍待使用观察。详见[记忆维护说明](docs/memory-maintenance-20261022.md)。


## 性格随相处成长

分群人设页新增成长开关、待观察反馈、已形成习惯、日志与撤回。真实互动反思与现有对话整理合用请求，依据反复反馈渐进调整闲聊篇幅、玩笑、语气、表情和分享表达；不改写核心人设。证据和时间条件满足后自动采用，意见冲突先观察，支持暂停和撤回；各群隔离，成长过程不向群刷消息。源码/语法和页面检查已完成，真实多轮效果待使用观察。详见[实现与边界](docs/personality-growth-20261022.md)。

## 摘要日期与事实对照

网页与 Steam 公告按原请求时间核对发布范围，区分发布、更新、事件/生效时间与检索时间。关键说法补充搜索并读取实际正文，逐条保留原文片段及出处；区分未独立证实、补充正文支持和来源分歧。日期标注、官网自述、百科内容、多个转载均不直接等于事实认证。贴文不上传搜索，核对失败保留范围说明。聊天设置中可展开“日期与事实怎样核对”。源码/语法及只读页面检查已完成，真实摘要效果待实际使用观察。详见[实现与边界](docs/summary-verification-20261022.md)。

## 旧转发与跨成员图片追问

引用原转发并 @bot 时，支持较早记录和同时 @原发送者，仍检查同会话与记忆重置边界。无引用的明确转发阅读请求会查当前会话近24小时、最多300条记录，多条候选请用户指定；普通“看看”仍只关联当前发送者3分钟内的来源。未关联、展开失败与图片读取失败分别说明。真实原转发已只读展开确认有16条节点/8张图片引用；未强制调用模型或发群消息，完整回复效果待实际使用观察。详见[关联修正](docs/forward-source-fix-20261022.md)。

## 从容接话与长回复分段

日常先回应内容，减少急着拒绝、指责和反复自辩；被纠正时核对并修正，保留有依据的不同意见。详细回答提高生成预算与正文保留空间，500字只触发折叠，长回复在同一张卡片内优先按段落分多条记录。普通闲聊仍短，角色和分群记忆保留。语法/静态及只读页面检查完成，实际语气和QQ显示仍待使用观察。详见[实现与边界](docs/conversation-style-long-replies-20261022.md)。
