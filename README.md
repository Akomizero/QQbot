# QQ 群聊机器人

本项目通过 NapCatQQ 的 OneBot 11 反向 WebSocket 接收 QQ 群消息和好友私聊。Node 服务、Web 管理页和 OneBot WebSocket 都只监听本机 `127.0.0.1`。原有指令管理、Tavily 搜索、OpenAI-compatible 模型配置和人格/表达风格设置均保留。

最新视频理解、自然接话、知识积累、表情内容检查、后台常驻和恢复方式见 [本轮更新与验证](docs/updates-20261020.md)。运行 `powershell -File scripts/install-autostart.ps1` 可安装当前用户登录自启、异常恢复和运行期间保持系统唤醒；需要停止时运行 `powershell -File scripts/stop-bridge.ps1`。

## 接收范围

- 群消息：`group_id` 必须是数字字符串并出现在群号白名单中。开启主动聊天后，普通文字可进入短期上下文；明确 @机器人时走及时回复流程。
- 好友私聊：`user_id` 必须是数字字符串并出现在 QQ 号白名单中。
- 临时会话、频道、通知、未知事件、非数字 ID、损坏的白名单和空名单都会默认拒绝。群聊和私聊名单彼此独立。
- 未授权消息在命令解析、附件检查、搜索、模型调用和回复之前被丢弃。
- 所有 OneBot ID 在 JSON 解码前保留为字符串，不转换为 JavaScript `Number`。回复使用 `send_msg` 发回来源群号或好友 QQ 号。
- 初始群白名单包含管理群 `[已脱敏QQ号]`；初始好友私聊白名单为空。

群内明确 @机器人，或提到已启用的昵称（默认“大肥鱼”“肥鱼”“鱼鱼”）时，先匹配管理页中的指令，再处理搜索意图，最后交给模型。其他群聊普通文字由主动聊天流程观察和合并话轮，不会逐条调用回复模型。好友私聊可使用同一批指令；普通私聊文字会交给模型。

同一群或同一好友私聊中需要直接回复的消息按到达顺序排队处理，实际发出回复至少间隔 10 秒；昵称、@、指令和私聊共用对应会话的队列。模型同时最多处理 2 个请求，其他会话等待空位，图片处理也排队等候。每个会话最多排队 50 条，队列只在内存保存，重启后不补发旧消息。

## 主动群聊

管理员可在管理面板为白名单群开启主动聊天；网页中可关闭或调整。只有通过群白名单的普通文字消息会进入进程内短期上下文，最多保留 15 分钟、每群 20 条、每条最多 400 个字符；上下文不写入磁盘。每次新消息会重置群聊停顿计时，默认停顿 8 秒后把这一轮最多 10 条近期文本交给模型，由模型结合人设判断是否回应、延续话题或自然地开启一个轻话题；若此刻不合适，模型应选择沉默。消息不会逐条调用模型：每群模型判断默认至少间隔 5 分钟，实际主动发言冷却至少 10 分钟，每群每天默认最多 3 次模型判断/主动发言（可调为 1 到 24 次）。计时器等待、评估频率、冷却和每日上限都可在网页调整。节流只保存每群判断/回复时间和每日计数到 `.local/proactive-chat-state.json`，不保存聊天内容。主动消息只发回产生该上下文的白名单群；关闭主动聊天会停止观察并清空内存上下文。

主动聊天会忽略自身消息、图片、机器人命令、搜索意图和包含 @ 的消息。明确 @机器人的消息仍按原有命令、搜索、模型和识图流程及时处理；好友私聊白名单逻辑不变。

“无人回应时暂停主动聊天”默认开启。主动发言后先等待回应，持续没人接话时静默，合计 65 分钟内不再主动插话；之后仍须满足频率和每日上限。@、呼唤昵称、引用其上一条主动发言会恢复参与；发言后 3 分钟内明显的接梗、短回应也可恢复。普通群友之间继续聊天不会自动解除暂停。管理员可在“主动聊天频率”调整该开关。

## 安装和配置

需要 Node.js 20.9 或更高版本。NapCat 请从 [NapCatQQ 官方 GitHub Releases](https://github.com/NapNeko/NapCatQQ/releases) 下载并在独立目录运行。此项目不会安装、修改或迁移其他 QQ 安装目录中的数据。

在项目目录运行：

```powershell
npm install
Copy-Item .env.example .env
```

在 `.env` 中填入至少 32 位的随机 `ONEBOT_ACCESS_TOKEN`，以及可选的模型和 Tavily API key。令牌、API key 不会由管理页返回或写入应用日志。NapCat 反向 WebSocket 客户端也需要在其本机网络配置中填写相同令牌；NapCat 会将自己的网络配置保存在 NapCat 配置目录。

默认设置：

```text
OneBot WebSocket: ws://127.0.0.1:16700/onebot/v11/ws
管理面板:         http://127.0.0.1:3000
```

需要修改时，可在 `.env` 设置 `QQBOT_ONEBOT_PORT`、`QQBOT_ONEBOT_PATH` 和 `QQBOT_WEB_PORT`。OneBot 服务不尝试抢占或终止其他进程；端口被占用时会启动失败并保留原进程。

## NapCat 配置

1. 从官方 Releases 解压一个独立的 NapCat 包并启动。
2. 在 NapCat WebUI 的「网络配置」中新增「WebSocket 客户端」（反向 WS）。地址填写 `ws://127.0.0.1:16700/onebot/v11/ws`，消息格式选 `array`，Token 填 `.env` 的 `ONEBOT_ACCESS_TOKEN`，启用后保存。若要启用图片识别，还需在 NapCat 配置中将 `enableLocalFile2Url` 设为 `true`，使 `get_image` 返回 Base64。
3. 在本项目目录运行 `npm start`。管理面板中的状态会显示 NapCat OneBot 是否已连上。
4. 打开 `http://127.0.0.1:3000`，分别填写允许的群号和好友 QQ 号。任一列表为空时，该类消息全部拒绝。

如果修改了端口或路径，以管理页展示的 WebSocket 地址为准。不要把 NapCat WebUI 登录令牌、OneBot 令牌或 API key 发到群聊或聊天记录中。

只启动本机管理页（不启动 OneBot 桥接）可运行：

```powershell
npm run web
```

## 管理面板

管理页按“聊天设置、知识库、表情包、接收范围、指令”分页；聊天页将常用开关放在前面，模型连接、人设、搜索来源、主动聊天频率按需展开。管理页可编辑群号/好友 QQ 号名单、指令、模型、人格、表达风格、搜索设置及图片开关。指令和设置保存在本机 `data/`。表达风格保留“网友聊天”和“角色扮演”快捷预设，点击后仍可继续编辑。

首次打开本机管理页时，请自行设置至少 12 个字符的管理员密码。服务端使用随机 salt 和 scrypt 保存密码哈希，不保存明文密码；签名密钥和认证文件保存在 `.local/admin-auth.json`，该目录已加入 `.gitignore`。登录会签发 8 小时有效的 HttpOnly、SameSite=Strict 签名会话 Cookie；连续 5 次失败后会暂时锁定 15 分钟。退出后需重新登录。所有管理数据 API（包括读取接口）都要求有效会话，并继续检查 Host/Origin。

管理服务只绑定 `127.0.0.1`，并只接受匹配本机地址的 Host/Origin；这限制远程网络访问，但不隔离同一台电脑上的其他进程或用户。首次设置遵循本机先完成者：请只在可信、非共享的电脑上完成，不要经端口转发、代理或其他方式暴露初始化页面。跨进程 `wx` 独占锁会阻止多个实例同时初始化，且锁文件不会自动删除。若页面提示存在初始化锁（包括强制结束进程后的残锁），先确认所有本项目实例都已停止，再手动删除 `.local/admin-auth.setup.lock` 并刷新页面重试。成功设置后该锁也会保留；正常登录不受影响。

`QQBOT_LLM_API_KEY` 是可选的模型 API key，`TAVILY_API_KEY` 与 `SERPER_API_KEY` 是网页搜索 key。密钥保存在服务端 `.env`，可在本机管理页只写入、替换或清除，页面不会回显已有值。备用 Exa MCP 和 B站公开视频搜索不使用 Tavily key。所有搜索只访问代码内固定的检索服务地址，不抓取模型指定的任意 URL。

模型 API 地址和模型名可在管理页设置，使用用户配置的第三方 OpenAI-compatible 服务。启用 AI 回复时，授权消息的文字会发送给该服务；启用识图后，经过校验的图片也会随请求发送。启用本地知识库时，只附加与当前问题匹配的知识片段。API key 保存在服务端 `.env`，管理页只能写入新 key，不会回显已有值或把它写入应用日志。

## 本地知识库与中文社区搜索

“成员印象”页新增按群号与QQ号分别积累的长期印象，可审核、编辑、停用、暂停积累或清除。明确“记住”的非敏感自述可生效，普通自述先待确认；同名不合并、不跨群或私聊使用。群友@bot说“忘记我”可清除并暂停，详见[成员印象说明](docs/member-impressions-20261021.md)。

登录管理页后，在“本地知识库”点击“添加知识”，填写标题、关键词/别名和正文。适合逐条积累网梗、角色背景和互动习惯；正文可按“含义/背景、适用场景、回复示例、不适用场景、来源和更新时间”组织。核心身份和每次都需要遵守的设定继续放在人设、表达风格或长期记忆中。

知识保存在 `data/knowledge-base.json`，不加入版本控制。手动和自动条目都只用于指定群，私聊资料另行维护；管理页先选择所属群。保存、停用或删除条目后下一次请求即生效，无需重启。最多 200 条、每条正文 12000 字符、总量 1 MiB。

“从群友聊天中积累知识”默认开启，可在知识库页随时关闭。只处理授权群的文字、图片附言和带引用的解释，短期缓存在内存，最多保留30分钟。单人明确解释、纠正或说“记住”也可形成候选，普通聊天通常至少2条后提炼；每群至少间隔5分钟、每天最多12次，会额外调用当前模型。只持久化提炼结果、来源指纹和状态/次数，不保存原始聊天或原图，重启不恢复聊天缓冲。

同一批中至少两位成员的两条支持消息可自动启用条目，其他候选先停用并列入“待确认”，由管理员检查后启用。每群最多 40 条自动积累资料。知识库页支持关键词和来源筛选，显示来源群与证据数。搜索结果不自动写入，群聊资料也不能改写人设、白名单或权限。

检索在本机完成，使用中文分词和关键词排序，长正文自动切成片段，每次最多取 3 个相关条目。它不需要额外的 embedding API，也不是模型训练；别名、简称和近义词有助于提高命中率。管理页“试搜”可预览结果，不会调用模型或外网。命中片段会随当前问题发送给配置的模型，作为不可信背景，不改变白名单、权限或系统规则。模型自然接梗，不会每次汇报检索过程。可在模型设置中关闭“本地知识库检索”。

联网搜索开启后，模型可以选择普通全网搜索、中文社区范围或独立的 `bilibili_search` 视频搜索。普通搜索依次尝试 Tavily → Exa MCP → B站；超时、服务错误、额度受限或空结果会尝试下一条通道。失败服务冷却 60 秒，成功结果在内存缓存 5 分钟。没有 Tavily key 时直接从 Exa 开始。

Tavily 的中文社区范围通过官方 [include_domains 参数](https://docs.tavily.com/documentation/api-reference/endpoint/search) 限定 B站、知乎、贴吧、百科、NGA 和机核等来源。备用 [Exa MCP](https://exa.ai/mcp) 使用独立服务检索公开网页，匿名额度受服务方限制，范围会扩大到全网；不是国内全站覆盖保证。B站视频搜索直接查询公开视频元数据，返回标题、UP主、时长、简介和链接，不需要登录 Cookie。它不是观看视频或提取字幕，模型不能据此声称看过视频或核实了实时事实。B站接口同样可能限流。

已安装的 `bilibili-cli` 和 `exa-web-search-free` skill 用于开发工具的检索指导。bot 在自身搜索模块中直接实现这些检索通道，不执行聊天传入的 shell 命令，也不需要启动额外的 MCP 子进程。

## 网页阅读与内容总结

在「聊天设置 → 联网阅读与总结」开启后，可以总结新闻、公告、文章、教程、技术资料、游戏更新，以及直接贴出的文字。例如：

- `肥鱼，帮我总结近期人工智能新闻`
- `肥鱼，总结这篇文章 https://公开文章链接 图文版`
- `/总结 某个主题或公开网页链接`
- `帮我总结以下文字：` 后粘贴原文。此方式无需联网，不将原文发送给搜索服务。

主题请求先使用现有搜索备用链找来源，再读取最多3个网页的正文；指定链接则直接读取。Tavily Extract 不可用时，尝试本机公开网页读取，不要求 Tavily key。只读取公开 HTTPS 文字页面，逐次跳转检查公开地址并校验证书；不支持需要登录的内容，无法取到正文时会说明并请用户贴原文。内容过长会标注截取；来源身份或“最新”顺序未核实时不作保证。

即使 Tavily 已取得正文，也会继续核对原网页的发布时间信息：分别读取发布、更新的元信息、Article 结构化数据以及明确的正文日期标注，摘要附日期依据。多处日期冲突、未来日期、原页无法核对或根本未标注时分别说明；不把任意活动日期、网址中的日期、搜索索引日期或 HTTP Last-Modified 当作首次发布日期。日期只有年月日时不补时分，时区缺失时注明；带明确时区的时间转成北京时间展示。这里核对的是发布者在原页的标注，不代表独立证实文章中事件发生的时间。

通用的近期资讯主题只采用原页可核对且发布时间落在筛选范围内的来源；“今天、昨天、本周、本月、近N天”按北京时间日期计算。未写具体天数时，“近期/最近”和新闻类“最新”默认近7天，其他“最新”默认近30天，实际范围会附在摘要中。没有合格来源时明确说明，不用旧文或无日期资料凑近期资讯。指定链接仍可总结，但日期缺失或超出所问范围时不能称为最新；Steam 专用频道的最新公告按该频道实际发布顺序判断。

可在管理页选择文字合并转发或图文长图，也可说「图文版」或「文字版」覆盖默认。图文使用深色分区卡片：顶部一句话结论、主题标题、紫色编号要点、蓝色强调框和青绿色步骤；来源与日期单独放在末尾，链接也保留为可复制文字。较长内容按章节与要点分页，单页不超过2600像素高，最多6页；排版失败时回退完整文字，不收藏为表情。普通分析问题也可明确说「肥鱼，用图文版分析……」，不必带“总结”关键词。普通闲聊的默认发送方式不变。

游戏更新是其中一个来源类型，Steam 开发者公告专用渠道继续保留。普通问答还可由模型自行调用 `read_webpage` 读取搜索找到的原文，每条回复最多2页。所有回复继续使用原有群白名单、独立群人设、发送队列与10秒间隔。

## 图片消息

授权会话发送图片后，机器人只取入站 OneBot 图片段的 `data.file`，并调用 `get_image`。它只读取返回值中的 `data.base64`；不会读取或传递返回值中的 `url`、`file` 或本地路径。NapCat 需启用 `enableLocalFile2Url` 才能返回 Base64；没有 Base64 时会拒绝处理。

默认看图回复是一两句自然的感受、接梗或回应，围绕整体情绪和当前话题。明确要求识字、细节分析或解决具体问题时再展开；不默认逐项描述画面，也不编造共同经历。长期知识从相关文字互动中提炼网梗、偏好和背景。

「聊天设置 → 图片与角色辨认」默认开启角色增强。入站图片使用高细节模式；先独立辨认动漫、游戏和虚拟角色的姓名、作品与可见特征，再以当前群人设自然回复。该辨认步骤不带聊天人设，避免将图中角色当成 bot 自身；证据只有发色等普通特征时降低确定性，认不出则说明。新图可能增加一次模型请求，短暂失败时继续使用原图聊天。相同图片的辨认结果在进程内缓存，按群隔离。真人图片不进行身份猜测。

管理员确认的公开虚构角色可保存于 `data/character-references.json`：只保存姓名、作品、可见特征和图片指纹，不复制原图。相同文件可直接沿用标注；近似指纹仅作候选，其他图仍需核对特征，不能只因资料库里有一个角色就认成此人。分群条目只用于本群；管理员提供的公共角色参考可设为通用，不与群聊知识、私聊资料或群人设记忆合并。当前已加入用户标注的《鸣潮》达妮娅示例。不能保证识别所有新角色、换装、遮挡或二创。

原始 JPG、PNG、WebP 或 GIF 每张最多 20 MiB、每条消息最多 2 张、原文件总量最多 24 MiB。送入模型的图片每张最多 4 MiB、总量最多 6 MiB；较大的普通图片会在内存缩小为 WebP，GIF 只取首帧，转换最长边 1600。普通图片缩小输入最多 4000 万像素，GIF 首帧最多 1600 万像素。原文件大小与模型输入大小分别计数，较大的 GIF 不再提前触发普通图片的 4 MiB 限制。

文件标识只允许预期的随机文件名（含 GIF 扩展名）；从 OneBot 返回的普通 Base64、带 data URL/base64:// 前缀或换行的 Base64 都会规范化校验。普通 QQ face/mface 或缺少可读取图片的商城表情作为表情提示交给模型，不走文件校验。图片读取排队，一次只处理一个在途请求；OneBot WebSocket 帧上限为 32 MiB，以容纳 20 MiB 原始文件的 Base64。图片识别关闭时不调用 `get_image`。普通识图不保存原图；启用表情学习时，被选中的表情会写入表情库。

## 让 bot 发表情包

在“表情包”页上传 JPG、PNG、WebP 或 GIF，填写名称及情绪/适用场景。文件保存在本机 `.local/stickers/`，最多 50 张、每张 20 MiB、总量 60 MiB；预览与管理接口需要管理员登录。手动上传保留原文件，GIF 发送时保留原动画。浏览器、上传接口、存储读取和 OneBot 图片链路均已同步调整大小限制。

开启表情包功能后，模型可通过 `select_sticker` 从已启用的表情里选一张随回复发送；每条回复最多一张，同一会话至少间隔 30 秒。不合适时只发文字，主动闲聊目前只发文字。聊天内容不能指定本地路径或任意图片 URL。未上传表情时照常文字回复。

“从群友的表情中自动学习收藏”默认开启。授权群发送 GIF 或 QQ 图片表情（`sub_type=1` 或商城表情图片段）时，即使没有 @，bot 也会择合适的通用表情收藏，自动命名、添加情绪/场景标签，并启用供以后回复选择。普通照片不进入自动收藏；筛选提示要求排除私人照片、聊天截图、二维码、联系方式等，无法确定时跳过。筛选额外调用当前模型，失败时静默，不向群里刷屏。

自动收藏按文件哈希去重，已停用的表情不会被重复学习覆盖。学来的表情只在来源群使用，管理员上传的表情是通用的；管理页显示来源并可编辑、停用或删除，点击“刷新列表”查看新收藏。每群至少间隔 2 分钟、每天最多判断 12 次，计数保存在 `.local/sticker-learning-state.json`，重启仍保留。自动收藏每群最多 15 张、全库最多 40 张，为手动上传预留数量空间。自动收藏的大图会尽量压缩至 3 MiB 以内；动图帧数过多或无法压缩时收藏静态首帧，管理页会标明；手动上传不做此收藏压缩。

在授权群中 @ 或呼唤昵称，并附图说“给你当表情包”“收藏这张图”等，可明确赠送普通 JPG/PNG/WebP 梗图。程序先保存并回执，再学习名称和用途；模型暂时断连也不会把已收到的赠送当作聊天失败。明确赠送与管理页上传一样保留原文件，仍受数量、总容量与来源群限制。

收藏不仅保存图片，还保存 `usage`（适用情境）和 `avoid`（避免情境）。自动收藏会一起提炼情绪、话题、社交语气；手动上传未填写用途时，后台使用当前模型看图补充，可在页面修改。连接暂时失败时先保留文件、最多重试 3 次，重启会继续处理待学习条目。用途尚未学好时不列入模型可发表情列表。回复时模型同时获得名称、情绪标签、适用情境和避免情境，结合当前对话决定是否使用，避免把夸奖、玩笑表情发到严肃或悲伤的场景。

模型请求使用服务端代理配置；普通回复开启自动补试时，每个模型步骤在共同60秒预算内最多请求2次（首次加1次补试），空回复也共用补试额度；关闭时仅1次。工具后续步骤、角色辨认和后台学习是独立任务。健康模型连接池短期复用，故障后重建；可用QQBOT_MODEL_PROXY_URL单独配置模型出口；失败给出诊断号，管理页可查看错误类别、HTTP状态和耗时。视频素材已读到但模型回答失败时会单独说明。诊断不记录接口地址、请求正文、图片或密钥。上游线路重置仍可能导致失败。

本轮P0实现与边界见 [修复记录](docs/p0-progress-20261021.md)。知识库新增待确认/拒绝与来源查看；表情页新增本群禁用和反馈审核。按成员长期印象已加入独立页面；完整角色参考管理仍待实现。
